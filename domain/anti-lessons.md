# Anti-Lessons — 負面教材集

## 這份文件在補什麼洞

既有三層機制各有職責，但都不保留**錯誤本身的長相**：

| 層 | 記什麼 | 不記什麼 |
|---|---|---|
| `git log` | 檔案異動 | 為什麼會錯 |
| `log/YYYY-MM.md` | 什麼時候做了什麼 | 錯的東西長什麼樣 |
| `domain/lessons.md` | 提煉後的**正確**規則 | 錯誤的外觀 |

在工程資料上，**錯誤的外觀才是關鍵資產**。「要查證出處」這條規則人人都知道，但看到一份格式完整的表格時，沒有人會停下來問它是不是機械重建的。規則救不了這個——能救的是把那份表格的**形狀**留下來。

## 條目格式

```markdown
## [N-XXX] 標題

- **類型**：TRANSIT | MISLEAD | MISJUDGE | BADDATA | EXPIRED
- **它看起來像什麼**：為什麼會被誤信。寫不出來就不要登錄。
- **實際是什麼**：真相。
- **怎麼發現的**：偵錯方法。這一欄是最可復用的部分。
- **反向練習**：可直接當考題的提問。
```

| 類型 | 定義 |
|---|---|
| `TRANSIT` | 中途資料——詢問中、待回覆、未定案，但看起來像結論 |
| `MISLEAD` | 誤導——字面為真，但導向錯誤結論。反駁不了它，因為它沒說錯 |
| `MISJUDGE` | 誤判——曾下過的結論，後被推翻，且可能已被引用 |
| `BADDATA` | 錯誤數據——數字本身是錯的，但格式完整看不出來 |
| `EXPIRED` | 失效——曾經正確，現在不是。新舊並存時取到哪份看運氣 |

## 紀律

1. **只追加，不修改既有條目**（同 `lessons.md`）。有新發展就追加新條目並在舊條目下加 `→ 見 [N-YYY]`。
2. **本檔為公開層，所有條目必須去識別化**——不得出現客戶名、專案名、人名、可回推的實際數值。保留的是**錯誤的形狀**，不是錯誤的內容。
3. 「它看起來像什麼」寫不出來 ＝ 這筆沒有教學價值，記 `log/` 就夠了。
4. 專案內、含識別資訊的原始登錄留在各專案自己的負面教材簿，不上這裡。

## [N-001] 追蹤系統的「已結案」不等於設計上的「已決定」

- **類型**：`MISLEAD`
- **它看起來像什麼**：問題追蹤系統（RFI/Issue 平台）的狀態欄明確顯示 `Closed`，有具名回覆者、時戳、完整稽核軌跡。從專案管理角度，這批問題已經結案，可以從待辦清單上劃掉。
- **實際是什麼**：回覆內容大量是**條件式**的——「取決於採購決定」「視後續確認」「原則同意但須……」。狀態機只認得「有沒有人回覆」，認不得「這句話能不能拿來畫圖」。實測某案 9 筆全數 `Closed`，可據以設計者僅 4 筆，**高估 2.25 倍**。
- **怎麼發現的**：不看狀態欄，逐筆讀回覆全文，對每一筆問同一個問題——**「拿這句話能不能直接進設計？」** 不能就不算結。
- **反向練習**：給一筆 `Status: Closed` 的完整 RFI 回覆，問「這一題結了嗎？可以往下設計了嗎？」
- **延伸**：任何以「已回覆數／已結案數」當進度指標的報表都會系統性高估。真正的指標是「可據以設計數」。

## [N-002] 軟體內建的預設值不是你的答案

- **類型**：`MISLEAD`
- **它看起來像什麼**：BIM 軟體的空間屬性欄位裡已經有一個數字，非零、單位正確、格式正確。它就在那裡，看起來是軟體幫你算好的。
- **實際是什麼**：那是軟體的**地區性預設值**（多為美規），與當地法規要求可能差一個數量級。實測某教學模型的內建外氣量欄位為 90 m³/h，同一空間依台灣建築技術規則建築設備編 §102 應為 965 m³/h——**差 10.7 倍**。
- **怎麼發現的**：把法規算出來的值與軟體欄位值並列比對。**只要沒有人主動填過，那個欄位就是預設值**——不是計算結果。
- **反向練習**：打開任一 BIM 空間屬性，指著一個非零數字問「這個數字是誰放進去的？」
- **延伸**：判準是「這個欄位有沒有被人碰過」，不是「這個數字合不合理」。預設值經常看起來很合理。

## [N-003] 部分判定的總量不能外推全案

- **類型**：`MISJUDGE`
- **它看起來像什麼**：已經判定完一部分（例如 69 個空間中的 29 個），總量算出來了，可以先發需求文件，剩下的之後補。數字有出處、算法正確、格式完整。
- **實際是什麼**：實測全數判完後總量為原值的 **2.2 倍**。未判定的部分往往不是隨機分布——先做的通常是簡單的、明確的；難判的留到最後，而難判的常常也是量大的。
- **怎麼發現的**：判完剩下的，再算一次。沒有捷徑。
- **反向練習**：給一份「基於 29/69 判定」的需求文件，問「這份可以發出去嗎？」
- **延伸**：發出去的文件被引用後，撤回的成本遠高於等它算完。正確處置是**標明母數並註記為暫定**，或乾脆不發。此處的正面規則見 `mep-space-demand-matrix.md` 的凍結關卡。

## [N-004] 布林旗標很誠實，但你問錯了問題

- **類型**：`MISLEAD`
- **它看起來像什麼**：API 或屬性面板回傳 `true`。旗標名稱聽起來就是你要的保證（例如「連接良好」「已驗證」「有效」）。
- **實際是什麼**：旗標字面上斷言的東西，和你需要的保證，是兩件事。它沒有說謊——**是你把它的斷言誤讀成你的需求**。條件未滿足時回傳的「否」，也不等於該機制不存在。
- **怎麼發現的**：看到布林旗標為 `true` 時，強制走兩步——**① 它字面上斷言的是什麼？② 那是不是我要的保證？** 兩步之間經常有落差。
- **反向練習**：給一個回傳 `true` 的連通性旗標與一份端點需求加總不符的報表，問「模型說連好了，為什麼數字對不上？」
- **延伸**：這是「假綠燈」的通用型態。同一模式也出現在 CI 綠燈、測試通過、檢查腳本 PASS——**檢查通過只證明「那個檢查通過了」**。

## [N-005] 機械重建的資料，警語必須嵌進本體

- **類型**：`BADDATA`
- **它看起來像什麼**：一份欄位齊全、附統計與衝突偵測的正式對照表，數百列。任何人打開都會直接引用。
- **實際是什麼**：從 PDF 文字層機械解析重建的，未經來源方確認。檔頭**確實**寫了「本表為機械重建，未經確認」——但那行在第 7 行，表格在第 20 行之後。**捲下去就看不到警語了。**
- **怎麼發現的**：檔頭的自我聲明。產生它的腳本把警語寫進**輸出模板**而非只寫在腳本註解裡，這是做對的地方；做不夠的是警語只出現一次。
- **反向練習**：給這份表的第 50 列，問「這一列可以直接填進計算書嗎？」（注意：只給第 50 列，不給檔頭）
- **延伸**：修法是讓警語**跟著資料走**——每一頁、每個區塊、或每列一個標記欄，而不是只在檔案開頭出現一次。長文件的檔頭聲明約等於沒有聲明。

## [N-006] 無 provenance 標頭的轉檔，一律不可引用

- **類型**：`BADDATA`
- **它看起來像什麼**：檔名正確、位置顯眼、是 markdown 所以可全文檢索。放在根目錄，比放在規範轉檔資料夾裡更容易被先找到。
- **實際是什麼**：管線建立**之前**的舊轉檔，沒有來源標頭、沒有頁碼標記，且格式轉換已摧毀表格的行列關係。內容看起來完整，但表格裡的欄位對應是錯的。
- **怎麼發現的**：與管線標準格式比對——**沒有 `> **來源**：` 標頭、沒有 `<!-- page N -->` 標記，就是管線外的產物**。這是機械可判的，不需要讀內容。
- **反向練習**：同時給一份有標頭與一份無標頭的同源轉檔，問「這兩份差在哪？哪一份可以引用？」
- **延伸**：所以 provenance 標頭不只是禮貌，是**可機械檢查的信任邊界**。QA/QC 應把「converted 目錄下存在無標頭檔案」列為 FAIL。

## [N-007] 頁碼會錯，引文不會

- **類型**：`MISJUDGE`
- **它看起來像什麼**：一份引用清單，每筆都有出處檔名 ＋ 頁碼 ＋ 逐字引文，格式嚴謹，看起來已經查證過。
- **實際是什麼**：頁碼是用全文擷取結果反推的，而全文擷取**沒有可靠的頁面邊界**。實測 104 筆中 13 筆錯，錯誤率 12.5%。且錯的那些外觀與對的完全相同。
- **怎麼發現的**：**機械重跑**——用逐字引文的最長片段去逐頁搜尋，比對命中頁與宣稱頁。人工抽查抓不到 12.5% 這種密度。
- **反向練習**：給一份附頁碼的引用清單，問「怎麼證明這些頁碼是對的？抽查五筆夠嗎？」
- **延伸**：兩條正面規則——① **引文優先於頁碼**作為定位依據；② 文件另有**自印頁碼**時，實體頁序與自印頁碼必須分別記錄並註明採用哪一種。

## [N-008] 函式庫的 round-trip 會靜默丟失你沒在看的東西

- **類型**：`MISLEAD`
- **它看起來像什麼**：一支正常的檔案處理腳本，讀進來、改一格、存回去。程式碼品質良好，跑完沒有任何錯誤，開啟輸出檔內容也對。
- **實際是什麼**：現代辦公檔案格式是 zip 容器，內含大量處理函式庫**不認得因此不會保留**的 entry——文件分級標籤、內嵌物件、繪圖層、執行緒註解、列印設定。實測某次 round-trip 後 entry 數從 35 掉到 12。**若被剝除的是客戶的機密分級標籤，回送即為合規問題。**
- **怎麼發現的**：比對 round-trip 前後的 zip entry 清單。**不是比對內容，是比對容器。**
- **反向練習**：給一支「讀 xlsx、改一格、存回」的腳本，問「這支可以用在客戶提供的檔案上嗎？」
- **延伸**：需回寫客戶檔案時，正確做法是**外科置換**——把檔案當 zip，只替換要改的那一個 entry，其餘 byte 原封不動。另一個做法是讓危險腳本**自己拒絕執行**（`raise SystemExit`），降級為純資料來源。

## [N-009] 覆蓋率是三層，壓成兩層會把別人的缺件記成自己的疏漏

- **類型**：`MISLEAD`
- **它看起來像什麼**：「清單說有 88 份，我們手上有 40 份，覆蓋率 45%」——字面完全正確，而且聽起來像**我們的工作沒做完**。
- **實際是什麼**：三層才對——**宣告存在 / 本機有（其中已處理 vs 未處理才是我們的工作量）/ 本機無（對方未提供，是待索取項，不是我們的缺口）**。壓成兩層在對外報告時直接吃虧，壓反了則會把自己的疏漏記成對方缺件。
- **怎麼發現的**：把「未提供」與「未處理」分開追蹤，各自有清單。合在一起就再也分不開了。
- **反向練習**：給「40/88 = 45%」，問「這個數字在說誰沒做完？」
- **延伸**：這是覆蓋率統計的通用治理規則，不限文件——測試覆蓋率、法規檢核覆蓋率同樣適用。

## [N-010] 增量作業的 skip 路徑，必須自己維持索引完整性

- **類型**：`BADDATA`
- **它看起來像什麼**：批次作業跑完了、檔案都在、索引也在、沒有任何錯誤訊息。第二次跑更快，因為增量邏輯生效了。
- **實際是什麼**：首次執行時因主控台編碼崩潰，**檔案已寫出但索引未寫**；再跑時增量邏輯判定「產出比來源新 → 已最新 → 略過」，於是索引**永久少一筆，且不會再被補上**。一次性的環境錯誤變成了永久性的資料缺漏。
- **怎麼發現的**：**對帳**——索引筆數與實際產出檔數比對。「跑完沒報錯」不等於「產出完整」。
- **反向練習**：給一支有 skip 分支的增量轉檔腳本，問「skip 的時候除了跳過，還需要做什麼？」
- **延伸**：兩處修法——① 治根因（輸出串流強制 UTF-8）；② 治結構（**skip 分支仍重讀既有產出、重算統計、寫回索引**）。只做①，下次換一種崩潰方式還是會漏。

## [N-011] 執行者的自陳不是完成證據

- **類型**：`MISLEAD`
- **它看起來像什麼**：一份格式完全正確的結構化回報——狀態欄 `OK`、成功數、失敗數、略過數俱全，敘述欄還帶具體細節：抽出了哪三份檔、共幾頁、放在哪個目錄。有數字、有路徑、有專有名詞。**看起來就是做完了。**
- **實際是什麼**：那件事從未發生。設定檔存在但從未被執行；另一筆的自報字元數是實際值的 **4.6 倍**。回報的**格式正確性**與**內容真實性**是兩件完全獨立的事，而人類（與下游程式）會把前者當成後者的證據。
- **怎麼發現的**：**不看自陳，查三個獨立來源**——檔案系統實際存在的檔案、資料庫／清單裡的欄位值、程式自己寫的完成旗標。三方交叉一致才算數。指令的 exit code 與執行者的自我總結**都不是證據**，因為它們都由同一個可能出錯的主體產生。
- **反向練習**：給一份細節豐富、格式完整的 `STATUS: OK` 完成回報，問「怎麼證明它真的做了？」
- **延伸**：這是 `[N-004]`「假綠燈」的**上游變體**——`[N-004]` 是旗標斷言錯了東西，這裡是**根本沒有旗標，只有自述**。結構性修法有兩種：① 讓查證者獨立於執行者（不同角色、不同上下文、唯讀）；② 把執行者的職責限縮成「只准引用實際指令輸出，不准做任何斷言」，從結構上消除它編造的空間。第②種在實務上更有效，因為它治的是成因而非症狀：會編造的，通常正是那些被要求斷言自己無法查證之事的角色。

## [N-012] 欄位名稱的語意漂移，比欄位缺席更危險

- **類型**：`BADDATA`
- **它看起來像什麼**：資料裡有個欄位叫 `pages`，值是整數 52，旁邊還有個 `empty_pages: 27`。拿它去對照「請見第 10 頁」完全順理成章。
- **實際是什麼**：對這個來源格式而言，那是**段落區塊的序號**，與該格式的實際頁碼毫無關係——那種檔案裡根本沒有分頁資訊（分頁由排版引擎在開啟時決定）。更關鍵的是：**正確資訊就在隔壁**（另有 `unit_kind: "block"` 與 `unit_count: 52` 兩個欄位如實記載），但一個熟悉的欄位名蓋過了兩個正確的欄位。
- **怎麼發現的**：拿**外部的真實引用**（別人的文件怎麼引這份資料）去反向驗證，而不是自己讀自己的 metadata。自我一致的 schema 不會自己暴露語意錯誤。
- **反向練習**：給一筆 `unit_kind: "block", unit_count: 52, pages: 52` 的 metadata，問「這份文件有幾頁？」
- **延伸**：修法是**讓不適用的欄位為 `null`，而不是填一個型別正確的近似值**。`pages: null` 會逼下游停下來問；`pages: 52` 不會。通用規則——**當一個欄位對某些成員不適用時，寧可缺值也不要借值**。借來的值會繼承那個欄位名的全部語意，包括你沒打算給的那些。

## [N-013] 檢查腳本的 PASS，涵蓋範圍比它的名字小

- **類型**：`MISLEAD`
- **它看起來像什麼**：一道自動化閘門輸出 `PASS  All domain-count claims == 79`。名字說的是「全部」，燈是綠的，退出碼 0，整份報告 60 項全過、零 FAIL、零 WARN。**沒有任何訊號提示你它只看了一部分。**
- **實際是什麼**：那句斷言的真正意思是「**我認得的那幾種寫法**一致」。閘門靠一份人工維護的樣式清單逐條比對，清單沒收錄的寫法一律靜默放行。實測把清單從 27 條擴大到 47 條後，同一批檔案立刻浮出 **16 處**過期計數，其中包含專案首頁與 README 開場句——都是被讀最多次的位置。閘門從未壞掉，它精確執行了它被寫出來要做的事。
- **怎麼發現的**：**不要問「檢查有沒有過」，要問「檢查看得到多少」。** 具體作法是拿一個**你已知是錯的**樣本餵它——沒抓到，PASS 的意義就此確定。這次的作法更省事：先擴大清單，讓真實存在但從未被抓到的缺陷自己現形。**用真實缺陷當負向測試，比造一個假樣本強**，因為它同時證明了「原本抓不到」與「現在抓得到」。
- **反向練習**：給一份 60 PASS / 0 FAIL 的稽核報告，與一頁寫著過期數字的公開網頁，問「報告是綠的，為什麼網頁是錯的？」
- **延伸**：這是 `[N-004]` 的**閘門變體**——`[N-004]` 是布林旗標斷言錯了東西，這裡是**檢查項的名字承諾了它的實作範圍以外的東西**。更惡劣的是它的失效方式：清單型比對在「命中 0 次」與「命中且全對」時輸出**完全相同**，所以只要有人潤稿改動了被比對的字面（多兩個字、把分隔符號換一個），該條就靜默歸零，而報告依然全綠。**涵蓋率會隨文件成長而衰減，且衰減本身不可觀測。** 兩段式修法：① 先加「零命中偵測」——每條樣式在全掃描集至少要命中一次，否則 FAIL。這不提高涵蓋率，但**讓涵蓋率的下降變成響亮失效**，後續改動才有安全網。② 再反轉預設值——與其列舉「哪些寫法要檢查」，不如宣告「凡是鄰近關鍵詞的數字都必須匹配真值，例外走白名單」，把漏網從靜默缺口變成一次性的、被審過的決定。**根治則是讓那些數字不再手寫**：由單一來源注入，閘門只需斷言「重新產生後無差異」——一條檢查、完整涵蓋、零樣式維護。
- **本條的誠實邊界**：16 處與 27→47 條均為**單一次稽核**的實測值，用於說明量級。「涵蓋率隨文件成長而衰減」是機制推論，非長期觀測結果。
