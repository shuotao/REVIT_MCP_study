Tools · 執行層
模型上真正被動到的那一下

Tool 是執行。它不決定方法，也不決定順序——方法在 Domain，順序在 Skill。這一頁把 239 個工具攤開，讓你看得到「有什麼」以及「哪些會動到模型」。

先看懂三個標記

每張卡右上角的標記來自 annotations.ts 集中產生的 annotations，不是這一頁另外標的。

  • 唯讀（95 個）——設計上不寫入 Revit 模型（export_* 與 capture_view_image 會另外寫出外部或暫存檔案）。
  • 會寫入（140 個）——會在 Transaction 裡改模型，但不刪除既有內容。可以 Undo，但會進 Revit 的復原堆疊。
  • 破壞性（4 個）——刪除或不可逆地取代既有內容：curate_mep_sizes · dedup_detail_elements_in_view · delete_element · import_excel_to_drafting_views。這份名單是白名單，程式碼裡多一個就會被閘門擋下。

「唯讀」是工具作者的宣告，不是執行時的沙箱。它告訴你這支工具設計上不寫入，不是保證它不可能寫入。

set_project_units
會寫入
base-tools
