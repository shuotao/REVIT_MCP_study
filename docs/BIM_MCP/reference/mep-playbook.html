機電設計教戰手冊
量從哪裡來，以及它怎麼變成可被檢核的東西

多數機電教材從「怎麼畫」開始。這一份不是——它從畫之前開始：那些數字的來歷。
它是 domain/mep-space-demand-matrix 的教學版，把一份方法論走成年輕工程師能實際依循的步驟。

從哪一章開始
  • 第一章：設計之前，量從哪裡來——先弄清楚數字的來歷
  • 第二章：把數字放進模型——需求如何變成可被檢核的東西
  • 第三章：設備與空間組成系統之後才解鎖的檢核——見下方章節卡

先講清楚它是什麼、不是什麼

演練標的：Autodesk MEP 認證課程的 Revit 2026 教學模型（門診型醫療建築）。非真實專案、非任何客戶案件——文中所有房間名稱與數值皆出自該教學模型。

方法出處：domain/mep-space-demand-matrix.md。方法定義以 domain 為準，兩者衝突時 domain 優先。

樣本數：一次完整實作演練，非跨案驗證的通則。案例數字皆為實測，錯誤紀錄照實保留。

這三件事要一起讀。第一件說它不會洩漏任何客戶資訊；第二件說它不是方法的最終定義，只是那份定義的教學展開；第三件說它的普適性有上限——在單一案例上成立的東西，不會因為寫得詳細就變成通則。

每一章末尾都有自己的「誠實邊界」小節，以類別列出該章自身的限制（第一章談引用等級與查證時效，第三章最細，逐項區分「模型讀回確認過」與「依 SOP 應該要有但尚未落地」）。那些小節不是免責聲明，是閱讀時該一起帶著的限制條件。

全書的脊椎：五種量

第一章的核心是一張分類法。它的用途不是學術分類，而是每個數字都要說得出它從哪來——當有人問「為什麼是這個數」，你要能立刻指出它屬於哪一種。

種類來源被問到時你要說得出
要來的建築、業主誰給的、哪一版
查來的法規、標準條號，以及你是讀原文還是轉引
算來的由前兩種推導公式，以及代進去的每一個輸入屬於哪一種
決定的 ⚠️判斷，沒有出處決定了什麼、依據什麼、誰決定的、日期與影響範圍
查無的 🔴沒有基準，不是你沒找到你查過哪些管道、給的是下限還是提出值、追蹤到哪

你可能在附冊的模型導覽看到「教學假設」這個字眼——那不是第六種量。它是 MEP_用途類別狀態 欄的其中一個值，把第四種「決定的」再細分成「技師判定」與「教學假設」兩級，只用來標記本演練模型裡哪些判定不具法律效力，不是這張表分類法的一員。

第四種是整套方法的重心。「決定的量」沒有出處可查——它是判斷。危險在於它一旦寫進模型，外觀就跟前三種一模一樣：都是欄位裡的一個數字。分不出來，就會把「有人決定過」誤讀成「查得到依據」。

第三章有一節叫「旗標誠實，但問題問錯了」，處理的是同一件事的下游版本：工具回傳的布林旗標沒有說謊，它精確回答了自己被設計來回答的問題——問題在於那不是你以為它在回答的問題。

它與 Domain、Skill、Tool 的關係

這份手冊不是第四層。它是 Domain 層的一份教學展開：

  • domain/mep-space-demand-matrix —— 方法的定義。原則、矩陣、轉換鏈、硬限制。衝突時以它為準。
  • domain/space-centroid-placement —— 同一批風口若要改成逐室批次放置（而非第二章的手動點擊），方法在這裡；第二章用的是手動放置，該節的重點在欄位住在哪一層（Instance/Type/Family），不是批次自動化。
  • 本手冊 —— 同一套方法的教學語氣版，補上 domain 不寫的東西：踩過的坑、錯誤的樣子、以及每一步為什麼是那個順序。

兩者的分工可以用一句話說完：domain 回答「方法是什麼」，手冊回答「第一次做的人會在哪裡卡住」。前者要精確，後者要誠實。

手冊教的是 Revit UI 的操作順序；同樣這些步驟若要改由工具執行，Tools 索引會標出哪一支是唯讀、哪一支會動模型。第三章的檢核之所以要等配管畫完才能跑，正是因為那些數值在那之前根本還沒被算出來。

誠實邊界

  • 單一案例。全書原則來自一次演練，不是跨案驗證的通則。
  • 部分法規為轉引。第一章與第三章（及附冊的結案模型導覽）以「法條明列／比照判定」標示 §102 的落點，但未逐條標明自身引用是讀原文或轉引——正式引用前請自行核對。
  • 「四類角色」等分類法無法源，屬工作方法。對業主不可以法規為由主張其必要性。
  • 查證有時效。第一章「台灣查無機房面積基準」是特定日期的查證結果，若日後取得公會設計手冊等來源，該節須更新。
  • 涵蓋範圍止於通風。空調設備選型、冷源架構、機房面積反算尚未定案，不在三章範圍內。
  • 本頁的「讀原文」連結指向 main 分支。手冊目前在待合併的分支上，連結會與這一頁同時生效。

最完整的限制條件在各章末尾的「誠實邊界」小節。第三章另外區分了兩種陳述：哪些數字是模型讀回確認過的、哪些是「依 SOP 應該要有但尚未落地」的規範性主張。讀到後者時不應把它當成前者。
