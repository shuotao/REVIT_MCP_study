## 前言：第一章結束時，你其實什麼都還沒檢查

第一章做完，每個房間都有了一個目標值——**但那個值只活在明細表裡**。

沒有任何東西在檢查它有沒有被滿足。你可以在明細表上填一個離譜的數字，模型不會有反應；你可以漏掉一整個房間，也沒有人會告訴你。

**第二章要做的，是把「一份計算」變成「模型自己會檢查的東西」。**

做完之後，模型會出現兩個並排的數字：

```
Specified（你要求的）  vs  Actual（實際做到的）
```

**這兩欄一旦並排，漏掉的房間、打錯的數字、放錯位置的設備，就藏不住了。**

## 一、先決定順序：拓樸先於數值

**第一章結束時最容易犯的錯，是急著開始算下一批數字。**

正確的下一步是**決定系統怎麼做**：集中還是分散、放哪一層、現在建還是預留、共用還是獨立。

### 為什麼

| | 拓樸決定 | 數值 |
|---|---|---|
| 誰能決定 | 業主／建築／機電**共同** | 機電自己算 |
| 改動代價 | **高**——動到建築空間 | 低 |
| 穩定度 | 定了就相對穩 | **會一直變** |

**業主通常先給你拓樸，數值在後面而且會一直變。** 若你把數值算到很細才去問拓樸，那些細算會整批作廢。

> **實例**：某案在決定通風系統型式之前，先把逐室通風量算完並交叉驗算過。
> 後來決定改採分層式，垂直風管需求從 0.74 m² 變成趨近零——**空間需求書整份失效**。
> 逐室風量沒有白算，但「依此風量提出的空間需求」白提了。

### 而拓樸決定會遞迴

不要以為決定一次就完了：

```
第 1 層  冰水 vs VRF      → 要不要機房
第 2 層  氣冷 vs 水冷      → 機房多大
第 3 層  集中 vs 分層      → 豎井多大、要不要
第 4 層  分層後機組放哪裡   → 要不要新的機房空間
```

**每一層都以為自己是最後一層。** 每一層都改變建築要留的空間。

## 二、兩條線要分開：通風先做，空調後做

**空調系統要冷房負荷；冷房負荷要六項輸入；那六項裡只有一項查得到。**

| 負荷分析要的輸入 | 台灣有法定值嗎 |
|---|---|
| 每面積外氣量 | ✅ 建築設備編 §102 |
| 照明負載密度 | ⚠️ 用電規則 §36 有，但那是**電力計算**用途 |
| 每人外氣量 | ❌ |
| 人員密度 | ❌ |
| 設備負載密度 | ❌ |
| 使用排程 | ❌ |

**其餘五項是「決定的量」。**

所以：

```
通風系統  ←  法定量已有，全部可交代　　→  先做
空調系統  ←  要五項猜來的輸入　　　　　→  後做，且必須先把假設記錄下來
```

> **原則：不要用猜來的輸入去驅動設計。**
> 能完全交代的先做，交代不了的先記錄成待決，不要混在一起做完再回頭分不清哪些可信。

### ⚠️ 軟體內建的預設值不是你的答案

Revit 的 Space 有 `Space Type` 與 `Construction Type`，內建就帶著上述六項的值——**但那些值來自國際標準（ASHRAE 系）**。

以某案的接待櫃檯為例：

| 來源 | 外氣量 |
|---|---:|
| 軟體內建預設 | **90 m³/h** |
| §102 候診室 15 m³/h·m² | **965 m³/h** |

**差 10.7 倍。**

**單位是對的、精度是對的，錯的是數值背後的標準。** 這種錯誤，單位盤點盤三遍也盤不出來。

**不要跑負荷分析之前不看輸入。**

## 三、值要進哪一欄——法規的款別決定，不是格式問題

法規列舉逐室通風量時，常同時規定**該用途允許哪幾種通風方式**。

台灣建築設備編 §101 有三款：

| 款 | 方式 |
|---|---|
| 第一款 | 機械送風 ＋ 機械排風 |
| 第二款 | 機械送風 ＋ 自然排風 |
| 第三款 | 自然送風 ＋ 機械排風 |

而 §102 的表格裡，**某些用途在第一、二款欄位是「－」**——代表**不得採用機械送風**。

```
可用第一款者   →  寫入「指定送風量」Specified Supply Airflow
僅可第三款者   →  寫入「指定排風量」Specified Exhaust Airflow
```

**對只能第三款的空間寫送風量，在法規上是錯的——而模型不會報錯。**

> **實例**：某案全案決定採第一款，但表中 13 個空間（廁所、更衣盥洗、刷手、暗室、清潔間、氣體室、茶水間）標明不得機械送風。
> 這 13 筆必須寫進排風欄。
> **款別分析原本被當成「數值不變所以不影響」而擱置，直到寫入這一步才發現它決定值進哪一欄。**

**所以第一章的用途判定，除了記係數，還必須記款別。** 只記係數的判定表，到這裡會缺料。

## 四、寫入模型的兩個陷阱

### 4-1 軟體的參數寫入可能走「內部單位」

專案單位設成公制、風量顯示 m³/h，**不代表寫入時也用 m³/h**。

Revit 的參數寫入走**內部單位**（英制系，風量為 ft³/s）：

| 你想寫 | 實際要給的值 |
|---|---|
| 89.2 m³/h | **0.875** |

換算率 **1 ft³/s = 101.9406 m³/h**。

**若批次寫入 46 筆而未換算，46 筆會全部大 102 倍——沒有任何錯誤訊息，明細表照常顯示、照常有總計。**

> **規則：寫入任何帶單位的參數之前，先寫一筆、讀回來核對。**
> 一次呼叫的成本，換掉整批資料靜默寫錯的風險。

### 4-2 批次寫入前，把作用視圖切離明細表

若當前開著的視圖就是那張多欄含計算欄位的明細表，**每寫一個參數就會重算一次整張表**，負荷累積後大量逾時。

實測：同一批資料，作用視圖為明細表時 7 筆全部逾時；切到一般平面圖後 14 筆一批秒過。

> **分辨方式**：唯讀查詢正常 ＋ 寫入逾時 = 前景視圖成本問題；兩者皆失敗 = 連線問題。
> **縮小批次不會解決前者，切視圖才會。**

## 五、實作：放風口

### 5-1 為什麼要在天花板平面圖放

吊頂風口的族群多半是 **hosted（需要宿主）**——它必須附著在天花板上。

**在樓層平面圖（Floor Plan）看不到天花板，放不上去。** 要用**天花板平面圖（Ceiling Plan / RCP）**。

> 如果某一間放不上去，**那間就是沒有天花板**。
> 這不是失敗，是一個發現——回去確認那個空間的天花設計。

### 5-2 步驟

**① 開啟天花板平面圖**

```
Project Browser → Views → Ceiling Plans → （選該樓層的 RCP）
```

**② 叫出風口工具**

```
Systems 頁籤 → HVAC 面板 → Air Terminal
```

**③ 在 Properties 面板頂端的 Type Selector 選族群與類型**

```
送風 →  Supply Diffuser - Square - Hosted  （尺寸依需求選）
排風 →  Exhaust Grill                       （見 5-3，這一步不能選錯）
```

> 🔍 **Type Selector 裡找不到你要的族群？** 那代表這個模型沒有載入它，不是你選錯地方。
> **見本章「附錄 A：模型裡沒有這個族群怎麼辦」**——那一節同樣適用於後面要放的風機與空調箱。

**④ 在天花板上點擊放置**

放在房間中央附近即可。多個風口時大致均分位置。

**⑤ 選取剛放好的風口，在 Properties 設定風量**

風量參數通常名為 `Flow`。填入該風口分擔的風量。

> 房間目標 964.6、放 5 個 → 每個填 192.9。
> **多風口時平均分即可**，前期不需要細算擴散半徑。

#### ⭐ 這一步會遇到一個 Revit 的基本觀念：你要改的東西住在哪一層

初學者最常卡在這裡——**「我找不到那個欄位」**。原因幾乎都是：那個值不在你以為的那一層。

| 層級 | 意義 | 要改它得做什麼 | 這個模型裡的例子 |
|---|---|---|---|
| **Instance（實例）** | 每一個元件各自一份 | **直接在 Properties 面板鍵入** | 風口的 **`Flow`** |
| **Type（類型）** | 同類型的所有元件共用一份 | **換一個類型，或 Duplicate 出新類型** | 風口的**面板尺寸**；FCU 的**容量** |
| **Family（族群）** | 寫在 `.rfa` 檔裡 | 開 **Family Editor** 改，再 **Load into Project** 覆蓋 | 風口的 `Pressure Drop`、箭頭顯示開關 |

**風量 `Flow` 是 Instance 參數**——所以你可以讓每一個風口有不同的風量，直接打上去就好，**不必複製類型、不必進族群編輯器**。

> **怎麼自己驗證某個參數在哪一層？**
> 選兩個同類型的元件，改其中一個。
> **只有那一個變 → Instance。兩個一起變 → Type。Properties 裡根本沒有這個欄位 → 它在 Family 裡。**

**這個對照值得記住，因為它會反過來教你設備怎麼選。**

`Fan Coil Unit` 的容量是**類型**：`600 / 800 / 1000 / 1200 / 1400 / 1600 / 1800 / 2000 CFM` 八個類型。你想把 600 改成 750，在 Properties 面板找不到欄位——**因為 Revit 的設計就是逼你選一台真實存在的機型，而不是打一個任意數字。**

反過來風口的風量是**實例**，因為每個風口的設計風量本來就該不同。

> **軟體把「什麼可以自由填」與「什麼必須從型錄挑」分在不同層級——那不是介面設計，那是工程慣例被寫進了資料結構。**

**⑥ 確認它被算進正確的空間**

放完之後，該 Space 的 `Actual Supply Airflow` 應該出現數字。**沒出現，就是風口沒有落在那個空間的範圍內。**

### 5-3 ⚠️ 連接器型別決定加總到哪一欄

**這是最容易踩、而且最難察覺的一個。**

軟體是依**風口的連接器型別**決定它加到哪一欄：

```
Supply  連接器  →  Actual Supply Airflow
Return  連接器  →  Actual Return Airflow     ← 不是 Exhaust！
Exhaust 連接器  →  Actual Exhaust Airflow
```

**排風的房間若放成 `Return Diffuser`：**

- `Actual Exhaust Airflow` 停在 **0**
- `Actual Return Airflow` 冒出數字
- **檢核顯示失敗——但看起來像是你放漏了**

`Return`（回風）與 `Exhaust`（排風）在中文口語裡常混用，但在系統上是兩件事：**回風送回機組再循環，排風直接排到室外。** 廁所是排風，不是回風。

**排風的房間，用 `Exhaust Grill`。**

### 5-4 要放哪些房間

**依樓層、依送排風分開列。** 大風量者標示建議風口數。

（實際清單依你的專案產出；本演練的清單見第一章結案模型的明細表，
依 `Specified Supply Airflow` 與 `Specified Exhaust Airflow` 兩欄篩選非零者。）

**篩選方法**：明細表加上這兩欄，非零的就是要放風口的房間。
送風欄非零 → 放送風口；排風欄非零 → 放排風口。**兩欄同時為 0 者不放**——那是判定為不適用的空間。

### 5-5 一個房間放幾個？這是「決定的量」

**沒有法定依據。**

實務慣例：**每個天花擴散器約 150–250 m³/h**，診療等噪音敏感空間取低值。

由此推：

| 房間目標風量 | 風口數 |
|---|---:|
| ≤ 250 | 1 |
| 250 ～ 500 | 2 |
| 500 ～ 750 | 3 |
| 750 ～ 1000 | 4 ～ 5 |

⚠️ **這個區間是慣例，不是規範。** 真實專案要依風口的擴散半徑、風速與 NC 值選型。

**依原則 4，它必須記進決策紀錄**——值、依據、決策者、日期。跟第一章的「決定的量」同一類。

## 六、檢核：模型第一次自己檢查自己

風口放完後，明細表加上這三欄：

```
Actual Supply Airflow
Actual Exhaust Airflow
Air Changes per Hour   （內建）
```

> ⚠️ **這三欄要等設備放完才加。** 提前加只會看到一整欄 0，
> 而一整欄 0 會被讀成「檢核不通過」或「資料遺失」——實際上只是設備還沒放。

### 檢核什麼

| 比對 | 抓什麼 |
|---|---|
| `Actual` vs `Specified` 逐室 | **漏掉的房間、打錯的數字、放錯房間的風口** |
| 兩者的總計 | 全案是否收斂 |
| 內建 `Air Changes per Hour` | 是否從 0 變成有值 |

### 誠實面對這個檢核抓的是什麼

**你把風口風量設成房間的目標值，`Actual` 當然會等於 `Specified`。那不是在發現新東西。**

**它抓的是遺漏與手誤。** 幾十間房間逐一人工核對必然會漏，明細表一列就看出來。

> 這與第一章「計算公式錯但外觀正常」是同一類防呆：
> **結果本身看起來都很合理，只有兩個獨立來源並排才看得出不一致。**

### 內建的換氣次數欄

第一章時它恆為 0，因為它吃的是 `Actual`（實際風口加總）或 `Calculated`（負荷分析輸出），而當時兩者都不存在。

**風口放完後，它應該會有值。** 那是這個模型第一次能用內建欄位做檢核。

> 如果放完仍為 0，代表風口沒有被歸屬到 Space——回頭檢查 5-2 的第 ⑥ 步。

## 七、這一章新增的「決定的量」

第一章講了五種量。第二章會產生**三個新的「決定的量」**，都必須記錄：

| 決定 | 依據 | 影響 |
|---|---|---|
| **主幹設計風速** | 無法定值。噪音敏感空間取低值 | 風管斷面 → 天花內淨空需求 |
| **每風口風量** | 無法定值。慣例 150–250 m³/h | 風口數量與配置 |
| **五項負荷輸入** | **無法定值，且客戶標準通常也沒有** | 冷房負荷 → 設備選型 |

> **第二章的教訓**：往下做一步，就多出幾個沒有出處的數字。
> **它們不會自己消失，只會被遺忘。** 每一個都要在當下記錄決策者與依據——
> 因為三個月後，你只會看到模型裡有個數字，看不出它是誰決定的。

## 附錄 A：模型裡沒有這個族群怎麼辦

**你會反覆遇到這件事**：Type Selector 打開，裡面沒有你要的東西。風口、風機、空調箱、泵浦——都會發生。

### A-1 先理解為什麼會這樣

**Revit 模型只帶著它「已經載入」的族群，不是帶著整個資料庫。**

這是刻意的設計：一個專案若把所有可能用到的設備都載進來，檔案會膨脹到無法使用。所以模型只有前一個人載過的東西。

> **「找不到」幾乎不是你操作錯，是這個模型還沒有它。**
> 這一步不是排錯，是正常流程的一部分。

### A-2 兩個名字很像、來源完全不同的功能

| 功能 | 從哪裡拿 | 什麼時候用 |
|---|---|---|
| `Insert → Load Family` | **本機硬碟**上的 `.rfa` 檔 | 你已經有檔案（公司族群庫、廠商提供、自己做的） |
| `Insert → Load Autodesk Family` | **Autodesk 線上內容庫** | 你沒有檔案，要用軟體原廠內容 |

⚠️ **不要假設本機一定有內容庫。**

> **本機實測（2026-08-14，單一台機器）**：
> `C:\ProgramData\Autodesk\RVT 2026\` 底下**沒有 `Libraries` 資料夾**——Revit 2026 完全沒有安裝本地內容庫。
> 同機的 `RVT 2024\Libraries` 有 446 個 `.rfa`，但「Traditional Chinese」語系只有 29 個（僅「結構預鑄」與「路徑分析」），**沒有機械／MEP 目錄**，搜尋檔名含 `Fan` 的族群**零命中**。
>
> 也就是說：**在這台機器上，`Load Family` 找不到任何風機，只有 `Load Autodesk Family` 拿得到。**
>
> 這是單機觀察，你的環境可能不同——**但值得先確認，而不是先假設。**

### A-3 `Load Autodesk Family` 對話框怎麼用

打開時預設是 `Category: Any`，會顯示整個庫（實測約 3,980 筆），依字母排序——**所以你會先看到一堆螺栓、Shoe Set、Step Surface，跟你要的完全無關。這不是壞了。**

縮小範圍有**兩個不同的軸**，先分清楚：

| 軸 | 是什麼 | 對你的意義 |
|---|---|---|
| **左上 `Filter → Category`** | **Revit 品類** | ⭐ **決定載進來會變成什麼東西**。這一軸最關鍵 |
| **左側 `Browse` 清單** | 內容庫的**資料夾結構** | 依主題瀏覽，適合你還不確定要什麼的時候逛 |

**先用 `Category` 過濾，理由不是它比較快，是它決定正確性。**

例如要找排風機：

```
Category → Mechanical Equipment      ← 設備
（不是 Air Terminals，那是風口）
```

**這兩者的差別在後面會咬人**：只有 `Mechanical Equipment` 能當一個風管系統的「基座」。你若誤載一個 Air Terminals 品類的東西當風機，放得下去、看起來像，但**建不出系統**。

### A-4 搜尋要用英文

**線上內容庫是英文命名的**——連對話框左側的 `Browse` 清單本身都是英文。用中文搜尋不會有結果。

| 你要找 | 英文關鍵字 |
|---|---|
| 排風機（通稱） | `fan`、`exhaust` |
| 管道式／天花內置 | `inline`、`in-line`、`duct` |
| 屋頂式 | `roof` |
| 離心式 | `centrifugal` |
| 通用／工業型 | `utility` |
| 空調箱 | `air handling` |
| 全熱交換器 | `energy recovery`、`heat recovery` |
| 冰水主機 | `chiller` |
| 泵浦 | `pump` |
| VAV 風機動力箱 | `VAV`、`fan powered` |

兩個實用細節：

- 搜尋框比對的是**名稱與路徑**，不是參數。**搜「500 CFM」不會找到 500 CFM 的機型。**
- 右上角有**清單／縮圖切換**。縮圖好看但難掃，**要比對名稱時切成清單**。

### A-5 🔴 載入之後、放置之前，先驗四件事

**載進來不等於能用。** 這四項每一項都會在後面某個步驟才爆，而那時很難回頭判斷是哪裡選錯：

| # | 檢查 | 不通過的後果 |
|---|---|---|
| 1 | **品類對不對**（設備要 `Mechanical Equipment`） | 放得下去但建不出系統 |
| 2 | **有沒有對應的風管接頭**（排風機要有 Exhaust／Return 接頭） | 系統建立時失敗，或接到錯的系統類型 |
| 3 | ⭐ **類型有沒有帶容量參數**（風量、靜壓） | **決定你後面能不能做「設備容量 vs 系統風量」的交叉檢核** |
| 4 | **類型序列涵蓋你的需求範圍** | 最小型號起跳就超過你的風量，等於選不到 |

**第 3 項最容易被忽略，代價也最大。**

### A-5-1 ⭐ 「類型名稱有數字」與「族群帶著性能資料」是兩件不同的事

**這一節是本演練實測四支族群後改寫的，初版把兩者混為一談。**

#### 🔴 先講一個查證方法上的陷阱——本節初版就是這樣寫錯的

**判斷「這支族群有沒有性能參數」，只讀類型是不夠的。**

| 讀哪一層 | 看得到什麼 |
|---|---|
| **類型（Type）** | 幾何尺寸、電壓、接管尺寸 |
| **實例（Instance）** | ⭐ **`Air Flow`、`External Static Pressure` 等性能參數** |

實測對照（`Exhauster with Cabinet` 300 CFM）：

```
讀型別 1365514  →  Fan Length/Width/Height、Duct Diameter、Voltage
                    ❌ 看不到任何風量或靜壓

放一個實例下去再讀  →  Air Flow 533.5
                       External Static Pressure 24.9 Pa
                       ✅ 兩者都在
```

> **這一節的初版因此下了錯的結論**（「這支族群沒有性能參數」）。
> **正確的查證動作是：載入 → 放一個實例 → 讀那個實例。** 只讀類型會系統性低估族群帶的資料。

#### 四支族群的實測對照

| 族群 | 類型名稱 | 性能參數（含實例層級） |
|---|---|---|
| **`Fan Coil Unit - Ceiling Ducted - CHW`** | `600 CFM` | ✅ 型別帶 **`Total Cooling Capacity` 5,774 W**、`Sensible` 4,220 W |
| **`Exhauster with Cabinet - Ceiling Mounted`** | `300 CFM` | ✅ 實例帶 **`Air Flow` 533.5**、**`External Static Pressure` 24.9 Pa** |
| `Centrifugal Fan - Inline - Direct Drive` | `380 CFM` | ⚠️ 型別只有幾何與電氣；**實例層級未實測**（同系列內容很可能也有，要放一個才知道） |
| `Air Handling Unit - Split System - Vertical` | `07` | ❌ 型別只有外型尺寸與電氣負載 |

**四支的類型名稱都像規格，但名稱本身從來不是資料。**

`Fan Coil Unit` 的 `600 CFM` 是名稱，`5,774 W` 才是參數（＝ 5,774 ÷ 3,517 ≈ **1.64 冷凍噸**）。`Exhauster` 的 `300 CFM` 是名稱，`Air Flow 533.5` 才是參數——**而這兩個數字換算後並不相等**（300 CFM ≈ 510 m³/h，不是 533.5），這本身就說明名稱與參數是兩套東西。

> 🔴 **這件事的後果比它看起來嚴重。**
>
> 名稱裡的 `380 CFM` **軟體讀不到**。你把一台名稱寫 380 CFM 的風機接到一個 46 CFM 的系統上，**Revit 不會有任何反應**——因為它不知道那台是 380。
>
> **「設備容量 vs 系統風量」這個聽起來很自然的檢核，在通用內容庫上做不出來。**

**由此得出三條規則：**

1. **判斷一支族群「有沒有規格」，要看型別參數，不能看類型名稱。**
2. **不要自己 Duplicate 出一個新容量的類型。** 你能改的只有幾何與電氣——**沒有風量欄位可以改**。名字改成 `100 CFM` 而沒有任何數字跟著變，等於造出一台不存在的機器，**而它跟原廠類型看起來一樣權威**。
3. **缺一個型號是看得見的缺口；一個手做的假型號是看不見的錯誤。** 前期寧可讓缺口留在模型裡。

> **前期若拿一支沒有性能參數的族群去做容量檢核，你會得到一份形式完整、但沒有任何獨立依據的表——而它看起來跟真的一樣。**

### A-5-2 這條界線就是「前期」與「後期」的分工

```
通用內容庫給的  →  幾何（外型、接管尺寸）
                    ↓
              前期用它做【空間包絡】——要跟建築要多大的房間

廠商族群給的    →  性能（風量、靜壓、效率、噪音、曲線）
                    ↓
              後期用它做【選型】——決定買哪一台
```

**所以「現在還不能選型」不是資料收集不足，是這個階段的內容本來就不帶那些資料。**

拓樸（哪些端點屬於哪個系統）**完全不需要性能資料**——這也是為什麼系統的框列可以先做，而選型必須等。

### A-6 誠實邊界

- A-2 的路徑與檔案數是**單機實測**，不同的 Revit 版本、語系與安裝選項會不同。
- A-4 的關鍵字是**常見英文機電術語**，不是線上庫的完整清單；庫的內容會隨 Autodesk 更新而變。
- A-5 第 4 項的「涵蓋範圍」要用**你自己算出來的風量**去對，不要用族群預設值反推需求——**那是把需求交給軟體決定。**
