## 🧩 先搞懂:MCP 是什麼?官方這次改了什麼?

### MCP 是什麼

MCP 全名是 Model Context Protocol,你可以把它想成**「讓 AI 助理能操作 Revit 的一套共同語言/接線標準」**。

就像不同廠牌的電動工具,只要接頭規格一樣,你就可以插上同一個插座使用——MCP 就是那個「共同接頭規格」。有了它,AI 助理(例如 Claude)才知道怎麼跟 Revit 溝通:「幫我建一道牆」「幫我查這個房間的面積」這類指令,才能被 Revit 正確接收並執行。

在我們專案裡,這個接線長這樣:

```
你(在 AI 助理裡打字)
  ↓ 走 stdio 連線(見下方說明)
中介程式(MCP Server,住在你電腦裡)
  ↓ 走 WebSocket(localhost:8964)
Revit 外掛(在 Revit 裡跑,負責真的動手做事)
```

其中幾個名詞先翻成人話:

- **stdio 連線**:AI 助理跟中介程式在你電腦裡直接對話的管道,不用透過網際網路,就像同一個工地裡兩個人用對講機講話,不需要打電話出去。
- **SDK**:官方提供的現成零件包/工具箱。我們的中介程式是用官方這包零件組出來的,不是自己從零焊接線路。
- **metadata**:貼在工具上的標籤,不改變工具本身怎麼用。就像一把電鑽貼了「小心燙手」的貼紙——貼紙本身不會讓電鑽變成別的工具,只是多一個提醒。

### 官方 2026-07-28 改了什麼

官方在這天發布了新版的「接線標準」,裡面大致分兩類東西:

- **(A) 加上去、對舊系統無害的改進**:例如幫工具貼更清楚的標籤、把工具清單排序固定下來、可以在對話裡顯示一個互動小視窗。這類東西不管你的 AI 助理新舊,都不會因此壞掉。
- **(B) 動到底層連線方式本身的大改**:例如換一種連線與登入方式、換一套「伺服器自我介紹」的機制。這類東西目前**連官方自己的「現成零件包(SDK)」都還沒出**——也就是說,連官方自己都還沒把這部分的正式零件準備好。

## 🧭 我們的原則:能加掛的先做,動主結構的先等

我們給自己定的規矩,用一句話講完:

> **官方改的東西,凡是加上去、對舊系統無害的,我們就先採用;凡是會改變「連線/溝通方式」本身的,我們先不動,等官方發正式的現成零件包(SDK)再說。**

用工地的比喻最好懂:

- 能「**加掛、不動主結構**」的裝修(比如加個標示牌、加一個好用的小面板),看到合理就先做,不會影響整棟樓的結構安全。
- 會「**動到樑柱主結構**」的變更(比如打掉一道承重牆),一定要等**正式圖說核准**才能施工,不會憑一張還沒定案的草圖就搶著動工——因為草圖之後很可能會改,現在做了將來還要打掉重做,反而浪費工夫、也可能傷到房子。

我們內部把這個做法叫做「雙時代並存(dual-era)」——意思是新標準跟舊標準**同時活著**,新工具能用新功能,舊工具照樣正常運作,不會有人被迫「二選一」。

## ✅ 我們實際做了哪 4 件事

以下 4 件事,全部屬於「加掛、不動主結構」,對你完全無害。

### 1. 每個工具都貼上「安全標籤」

我們專案裡的 167 個工具,現在每一個都貼上兩種標籤:

- **人看得懂的標題**(例如把工具代號翻成一句白話說明它在做什麼)。
- **「唯讀嗎/會不會破壞東西」的標示**——會不會只是「看一眼、查資料」,還是「真的會改動模型」。

比喻:就像工地機具貼上「唯讀觀看/會動到模型」的標示牌。AI 助理看到標籤,就更清楚哪些工具是安全的(比如查詢房間面積),哪些要小心(比如刪除元件這種真的會動到模型的,才會被標成「有破壞性」)。

**為什麼對你無害**:這只是「貼標籤」,工具本身怎麼呼叫、做什麼事完全沒變。如果你用的 AI 助理比較舊、看不懂這些標籤,它就會直接忽略,不會出錯、也不會少功能。

### 2. 工具清單固定照名字排序

以前 AI 助理跟中介程式要「工具目錄」的時候,清單順序可能每次不太一樣。現在改成**一律照工具名稱排好**再給出去,每次都是同一個順序。

比喻:像圖說目錄照編號順序排好,方便對照、方便找,不會今天這樣排、明天又換一種排法。

**為什麼對你無害**:你叫用工具,一律是叫它的「名字」(例如「幫我查詢房間資訊」),不是靠它在清單裡排第幾個。所以排序怎麼變,都不影響你實際使用。

### 3. 第一個「對話裡的互動小視窗」——碰撞檢查工具

我們的碰撞檢查工具(`detect_clashes`,用來抓 MEP 管線跟結構之間的干涉)現在多了一個新玩法:**在支援的 AI 助理裡**,執行完會直接在對話裡跳出一個互動表格,列出所有碰撞清單,還可以按按鈕「在 Revit 上色標示」「定位到該元件」。

比喻:就像在對話裡直接嵌一張可以點的檢討表,不用你自己再手動去 Revit 裡一個一個找。

**這個互動表格只會出現在「圖形介面」的 AI 助理**——因為「可以點的面板」本質上要有畫面才顯示得出來,終端機(純文字畫面)天生做不到。所以請先對號入座:

- **看得到互動表格**:用有支援「MCP Apps」的圖形介面宿主——例如 **Claude Desktop、claude.ai 網頁版、VS Code 的 GitHub Copilot** 等。(MCP Apps 是官方 2026-01-26 上線的互動介面擴充。)
- **看不到、只會是文字**:用**終端機 CLI**(例如 **Claude Code**)。終端機就是一片純文字,長不出可以點的表格,所以你一定是拿到文字版結果。這**不是故障**,碰撞檢查的正確性跟圖形版完全一樣。老實說,現在**多數人是用 CLI**,所以多數人平常不會看到這個表格,是正常的。

**為什麼對你無害**:不管你的 AI 助理支不支援這個互動視窗,`detect_clashes` 都會照常回傳完整的碰撞結果——支援的宿主多一張好看好點的表格,不支援的就是純文字,兩種都對。其他 166 個工具完全不受這件事影響。

> 誠實補充:這個碰撞檢視面板已通過「結構/規格」的自動驗證,但**我們還沒有在 Claude Desktop 上實際跑過一次畫面實測**;理論上會顯示,實務上請以你當下看到的結果為準。

### 4. 升級了官方零件包(SDK),從 1.22 版升到 1.30 版

這是為了讓上面第 3 點的互動小視窗能運作,我們把中介程式所用的官方零件包從 1.22 版升到 1.30 版。

**重點要澄清一下**:1.30 這版零件包,講的還是**舊版的溝通協定**(依然相容舊版 AI 助理),**所以這不等於我們已經切到官方 2026-07-28 那個新版「接線標準」**。底層溝通方式還是原本那套穩定、舊的、大家都能用的版本。

## ⏸️ 我們刻意「先不做」的部分(延後清單)

這是本文重點之一,值得認真解釋一下「為什麼」。

官方在 2026-07-28 這版裡,有幾樣**真正動到底層連線方式**的大改:

| 項目 | 白話說明 |
|---|---|
| Stateless(無狀態)連線模式 | 換一種「每次都重新自我介紹」的連線方式 |
| server/discover | 伺服器自我介紹的新機制 |
| resultType | 回傳結果型別的新規則 |
| Tasks core | 原生支援「背景長時間任務」 |
| HTTP / OAuth 傳輸與授權 | 換一種連線跟登入(身分驗證)的方式 |

以上這**五項,我們全部先不做**。

**為什麼先不做**:目前官方**連支援這版標準的「現成零件包(SDK)」都還沒發布**。如果我們現在自己硬幹、自己猜官方最後會定案成什麼樣子,萬一猜錯,等官方正式版一出來,我們很可能得把這段整個打掉重做——這樣反而會害到所有 fork 這個專案的人,因為你們用的功能可能又要跟著改一次。

所以我們的做法是:**等官方的正式零件包(SDK)出來、確定支援這版標準之後,我們才動手做**。

而且,我們不是「放著不管、忘記追蹤」——我們有一個**每天自動巡邏的機制**,專門在盯官方進度,一旦條件成立(官方 SDK 支援了),就會自動排進我們的實作排程,不需要你或任何人手動去追新聞、查更新。

用工地比喻收尾:**結構主體的變更,一定要等正式核准圖說才施工,不會憑一張還沒定案的草圖搶做。** 這樣蓋出來的房子才穩。

## 🙋 你需要做什麼?

答案幾乎是:**不用動。**

具體說明:

- **stdio 連線方式沒變**。你電腦裡既有的 Revit 外掛(就是那個負責跟 Revit 溝通、走 `localhost:8964` 的服務)完全不受影響,**不用重新編譯、不用重新安裝**。
- **舊的 AI 助理 + 舊的 Revit 外掛 + 新版中介程式,可以直接互通**,不會因為這次升級而斷線或壞掉。
- 換句話說:**現有使用者不需要採取任何行動。**

### 如果你想試試看新的互動小視窗功能

想看到上面第 3 點那個「可以點的碰撞表格」,重點只有一個:**要用「圖形介面」而且有支援 MCP Apps 的 AI 助理**。用最白話的方式分辨:

1. **想看到互動表格 → 用 Claude Desktop**(或 claude.ai 網頁版、VS Code GitHub Copilot 這類圖形介面)。正常呼叫 `detect_clashes` 就好,操作方式完全不用改。
2. **如果你是在終端機 CLI(例如 Claude Code)裡用 → 你會看到文字結果,而且一定是文字。** 終端機沒有辦法顯示可以點的面板,這是正常的,不是壞掉。目前多數人都是用 CLI,所以平常看到文字是常態。
3. 不確定你的助理支不支援?最快的方法:**直接跑一次 `detect_clashes`,跳出來是表格就是支援、是文字就是不支援。** 文字結果本身完全夠用,不影響碰撞檢查的正確性。

## 📌 fork 貢獻規則(提醒一下,沒有變)

這次升級**沒有改變**我們對 fork 貢獻的規則,藉這個機會提醒一下:

- 請**不要手動修改**由維護者管理的程式碼(例如 `MCP-Server/src/`、`MCP/` 這些資料夾)。
- 你們的知識型貢獻,請走 `domain/*.md`(專業 SOP 文件)和 `.claude/skills/*/SKILL.md`(技能說明)這兩個管道提交。
- fork 出去開的 PR,我們只收「知識型貢獻」,不收「改程式碼」的 PR——這條規則有自動化機制(CI)在把關,不符合的 PR 會被自動判定不通過。

老實說,**你們的價值不在改底層程式**,而在你們累積的**建築專業知識**——目前我們已經有 75 份專業 BIM SOP(`domain/`)、50 個對應的 AI 技能(`.claude/skills/`),都是靠像你們這樣有實務經驗的老師一點一滴貢獻出來的。這才是這個專案真正寶貴、AI 自己生不出來的部分。

## ❓ 常見問題

**Q1:我是現有使用者,要重裝或重新設定嗎?**
不用。這次是「加法式」升級,你原本的東西照樣可以用,什麼都不用動。

**Q2:我的 AI 助理不認得新的標籤(標題、唯讀/破壞性標示)會出錯嗎?**
不會。這些標籤是選填的,舊版 AI 助理看不懂就會直接跳過、忽略,不會因此當機或出錯。

**Q3:工具清單的排序改了,會影響我嗎?**
不會。你叫用工具一律是用「名稱」去叫,不是靠它在清單裡排第幾個,所以排序怎麼變都跟你無關。

**Q4:那些「動到底層連線方式」的大改(像是背景任務、換一種登入方式)什麼時候會做?**
目前沒有固定時間表,要等官方發布支援這版標準的正式零件包(SDK)之後才會動手。我們有每天自動巡邏的機制在盯這件事,一有進展就會自動排進實作排程,不需要你自己去追蹤。

**Q5:我 fork 了這個專案,可以順手改一下程式碼嗎?**
請不要。程式碼是由維護者管理的,fork 出去的 PR 請走知識型貢獻(`domain/` SOP 文件、`.claude/skills/` 技能說明),這樣你的專業知識才能被好好保留跟推廣。
