# 台中固定鐵皮施工圍籬元件

`export_families.constructionFence` 可在 Revit 2024 建立獨立通用模型 RFA。2025／2026 可升級使用；不可反向另存舊版本。此模式不載入或放置元件、不修改目前模型，也不修改外掛或連結設定。

依據：[臺中市建築物施工管制辦法第17條](https://law.taichung.gov.tw/LawContent.aspx?id=GL001332)，查核日期 2026-11-02。一般固定密閉式圍籬金屬板厚至少 1.2 mm，高度 2.4～4.5 m，底部應設防溢座。轉角、告示、警示燈及適用案件綠美化仍須依現場配置另行辦理。

預設單元寬 2400 mm、高 2400 mm、平面鐵皮厚 1.2 mm，底部與防溢座搭接 20 mm。包含兩端 L60×60×5 立柱、三道同尺寸橫桿、兩道斜撐與 200×200 mm 混凝土防溢座。斜撐以 50×50 mm 實心斷面示意，後伸 900 mm。**單元寬、骨架、斜撐、防溢座尺寸是建模假設，不是法規指定或經核定的結構設計。**錨定、基礎及抗風須另行設計。

原點在單元左端地面；X 為單元寬，Y 正向為工地內側，Z 向上。每單元包含兩根立柱，連續排列時須處理共用柱細節。

修正版使用參考平面、鎖定對齊及拉伸端點關聯，讓「單元寬度」「圍籬高度」「鐵皮厚度」類型參數驅動實體。舊版 `_固定` 參數僅為記錄，不能伸縮；請改用名稱含「可調式」的新 RFA。在專案中選取元件→編輯類型→修改尺寸；要保留舊尺寸時先複製類型。`連動_...` 為內部公式，請勿解除。族群名稱的尺寸為建立時初始值，不會隨類型參數自動改名。

支援單元寬1200～3000mm、高2400～4500mm、板厚1.2～3mm。Revit族群編輯器不會自動阻止所有超出範圍的數值，請遵守上述範圍。斜撐連接高度固定1680mm、平面位置隨寬度移動；斜撐並不隨圍籬高度改變坡度。

指定 `constructionFence.door: {"widthMm":1000,"heightMm":1200}` 可加入置中、由地面起的1m×1.2m淨開口、小門門扇、門框與把手示意；新增可調「小門淨寬」「小門淨高」。門保持關閉姿態，未設開啟角度參數。門扇周邊留5mm施工縫；門口防溢座與低橫桿斷開，排水阻隔另依現場處理。門淨寬至少600mm且不大於單元寬減200mm，淨高至少800mm且不大於圍籬高減200mm。

每次生成先改成兩組替代尺寸，逐一驗證所有實體外框，再恢復指定尺寸。另存重新開啟後，再測試一次寬、高、板厚變動並回滾；任一幾何驗證失敗不交付 RFA。編譯成功不等於這些 Revit 實機測試已通過。

呼叫範例（路徑由所在電腦提供）：

```json
{
  "outputFolder": "D:\\FamilyLibrary\\Fence",
  "constructionFence": {
    "templatePath": "D:\\ProgramData\\Autodesk\\RVT 2024\\Family Templates\\Traditional Chinese\\公制通用模型.rft",
    "widthMm": 2400,
    "heightMm": 2400,
    "sheetThicknessMm": 1.2
  },
  "dryRun": true,
  "apply": false
}
```

預覽後以 `dryRun=false, apply=true` 建立。若同名檔案存在，拒絕覆寫，請另選輸出資料夾。建立後先另存暫存 RFA，重新開啟驗證原生實體數量與外框尺寸，再搬到正式檔名。編譯通過不代表 RFA 已產生；以工具回傳 `ReopenedAndVerified=true` 為實際生成驗證結果。

## 既有折疊式大門的族群約束修復

`export_families.familyConstraints` 用於檢查與修復既有 RFA，與上述新建鐵皮圍籬模式不同。它不會自動把任意族群修好；必須先檢查原族群，再提供明確的尺寸公式、巢狀參數關聯、參考平面與草圖約束步驟。

- `mode=inspect`：未指定 `sourcePath` 時讀取作用中的族群；指定本機 RFA 時使用暫存副本，`familyPath` 可依名稱深入巢狀族群。回傳族群參數、尺寸參考、草圖端點、模型元件與實體包圍範圍。座標為 mm；族群參數的原始 Double 值則是 Revit 內部單位（英尺）。
- `mode=repair`：必須提供 `sourcePath`、新 `fileName`、`steps` 及至少兩個不同預期寬度的 `flexCases`。宣告式操作限於族群文件內的參數、關聯、尺寸、對齊、參考平面、位置與直線草圖，不接受執行程式碼。
- 修復及測試都在獨立副本執行；不載入目前專案、不儲存中央模型、不修改原 RFA 或 TYBIM。新增約束錯誤／警告會使交易回滾，不以刪除約束消除錯誤。
- 每個 flex 測試實際提交 Revit 交易以觸發約束檢查，再量測實體幾何，最後用 TransactionGroup 還原。`expectedWidthMm`／`expectedHeightMm` 檢查整體尺寸；`elementChecks` 檢查個別部件的 min/max 座標。只有整體外框通過，不能代表門片接縫已正確，仍須個別部件與目視檢查。
- 預設 dry run；正式輸出須 `apply=true,dryRun=false`。所有測試通過後才另存，重新開啟再重跑測試，最後發布新版 RFA。禁止覆寫既有輸出。修復功能編譯完成並不等於任何特定大門已通過測試。
